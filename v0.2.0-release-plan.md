# Kranz v0.2.0 release plan

## What the crates provide

For a normal user, the four crates provide one installable product:

```bash
cargo install kranz --locked
```

That installs the `kranz` command. Cargo automatically downloads and builds
the other three crates; they are not separate programs the user must install.

A crate is a packaged unit of Rust code, roughly equivalent to an npm or
Python package. A crate can produce either a binary—an executable command—or a
library containing reusable code for other Rust projects. crates.io is Rust's
public package registry, and Cargo is its package manager and build tool.

| Crate | What it provides |
| --- | --- |
| `kranz` | The CLI: drafting and running missions, approvals, validation, reporting, `kranz serve`, and the embedded dashboard. |
| `kranz-engine` | The core mission machinery: agent backends, worktrees, state and event logs, gates, validators, sandboxing, evidence, and controlled merging. |
| `kranz-server` | The reusable REST/WebSocket mission host used by `kranz serve`, the dashboard, and potential custom front ends. |
| `kranz-slack` | The reusable Slack Socket Mode bridge for operating and observing Kranz missions through Slack. |

A useful mental model:

- `kranz-engine` is the machinery.
- `kranz-server` is the network control room.
- `kranz-slack` is an operator-console adapter.
- `kranz` assembles them into the product people run.

Publishing all four is necessary because the CLI depends on the three
libraries. It also lets Rust developers embed parts of Kranz with commands such
as `cargo add kranz-engine`. At v0.2.0, those library APIs should be described
as early and evolving, not as a stable SDK.

crates.io does not provide precompiled software. `cargo install` compiles Kranz
locally and requires a Rust toolchain. GitHub binaries—and eventually
Homebrew—will be the easier installation route for most users. Kranz also does
not install or authenticate the underlying agent CLIs.

The public release message should be simple: **install the `kranz` crate; the
other crates are its reusable internal components.**

      every origin branch, tag, and pull-request ref.
