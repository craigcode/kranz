## Milestone 1 — Command-broken contract assertions escalate to the operator instead of burning fix cycles

### 1.1 Escalate author-broken final-gate command assertions to the operator

GOAL. Add a third outcome to the final-gate finding-conversion turn so that when the orchestrator judges a FAILING contract command assertion to be author-broken (a false negative: the underlying requirement is met, verified by the milestone validators that already passed, but the assertion's own command still fails), the engine escalates to the operator by BLOCKING with a precise message — instead of the current behavior of synthesizing fix-features and burning the fix-cycle cap on gate-repair. Everything you need is below; assume you have read nothing else.

ALL CODE CHANGES ARE IN crates/engine/src/orchestrator.rs. Tests go in crates/engine/tests/mission_test.rs. One short doc note in docs/knowledge/validation/gates.md. DO NOT edit crates/engine/src/types.rs or crates/engine/src/events.rs — they are CONTRACT FILES; this feature is designed to need no change there.

BACKGROUND (current code, orchestrator.rs):
- final_gate() (~line 4189) runs each check="command" contract assertion itself via run_shell_command. A non-zero exit becomes a Finding with severity="critical" and class="command-assertion" (~line 4260). Finding is defined in types.rs: { subject, severity, evidence, suggested_fix, class } — subject is the assertion id, evidence is the scrubbed 'command failed: <cmd>\n<output>'.
- final_gate emits a ValidationFinding event per finding, computes command_subjects (the set of subjects whose class=="command-assertion"), then calls convert_findings(&last_milestone_id, &all_findings) and matches its result. Command-assertion findings are NON-WAIVABLE: a Waive covering any command subject is refused and replaced with synthesized fix features, blocking at the cap (see the Waive arms ~4305-4366 and the Fix arm ~4367-4398).
- convert_findings() (~line 4039) runs ONE orchestrator JSON turn via self.json_decision::<FixFeaturesDecision>(&message), parsing into FixFeaturesDecision { fix_features, waived, summary } (structs at ~147-175). It returns enum FindingsConversion { Fix { specs, summary, text }, Waive { waived } } (~202-213). convert_findings is SHARED by both validation_round() (~3699) and final_gate().
- fix_cycles bumps ONLY when a fixfeature.created event is folded while the milestone status is Validating (reducer.rs ~322-324). Therefore an escalation path that emits NEITHER MilestoneValidating NOR FixFeatureCreated leaves fix_cycles untouched — this is how you satisfy 'fix_cycles accounting unchanged'.
- MilestoneBlocked { milestone_id, reason } already exists, already routes to the operator via handle_blocked (~2602), and already renders on Slack/tail. Reuse it — the reason string IS the operator message. Do not add a new event.

IMPLEMENT:
1. Add a decision struct near FixFeatureSpec/WaivedFinding (~147-175), e.g. #[derive(Debug, Deserialize)] #[serde(rename_all="camelCase")] struct CommandBrokenFinding { subject: String, #[serde(default)] diagnosis: String }. Add a field to FixFeaturesDecision: #[serde(default)] command_broken: Vec<CommandBrokenFinding> (defaulted so existing/old-shape answers still parse).
2. Add a variant to FindingsConversion: Escalate { escalations: Vec<CommandBrokenFinding>, text: String }.
3. In convert_findings(): after parsing the decision, before deciding Fix vs Waive, filter d.command_broken to keep ONLY entries whose subject matches a finding in `findings` with class=="command-assertion" (the escape-hatch guard — a subject that is not a command-assertion finding, e.g. an agent-judgement finding with class=="", MUST be dropped and flow to the normal fix/waive handling; it must never escalate). If, after filtering, at least one escalation remains, return FindingsConversion::Escalate { escalations, text } (escalation supersedes fix/waive for that round — the milestone is going to block anyway). Otherwise fall through to the existing Waive/Fix logic UNCHANGED. Remove any escalated subjects from consideration by the fix/waive branches so they are not double-handled.
4. Update the convert_findings prompt string (~4045-4054) to describe the third option and its guardrail. Add to the JSON shape a "commandBroken":[{"subject":"string","diagnosis":"string"}] array, and explain: use it ONLY for a contract COMMAND assertion you judge to be author-broken (the requirement is genuinely met — the milestone validators passed — but the assertion's own command is wrong, e.g. it can only pass pre-change, or counts the harness's own commits). It escalates to a HUMAN operator (blocks the mission); it is NOT a way to dodge a real product defect, and it is ignored for anything that is not a command assertion.
5. In final_gate()'s match on convert_findings(...) result, add an arm for FindingsConversion::Escalate { escalations, text }. It must: (a) emit_decision(summary, Some(text)) where summary names the escalated assertion subjects and states they appear to be author-broken command assertions being escalated to the operator (include each subject + its diagnosis and note evidence is attached); (b) emit EventKind::MilestoneBlocked { milestone_id: last_milestone_id, reason } where reason NAMES the assertion id(s) and reads like: 'contract command assertion(s) <ids> appear buggy (false negative) — command still fails but the requirement is verified met; evidence attached. Escalating to operator (gate-repair is a human decision, not a fix cycle).' Include the failing-command evidence in the emit_decision detail (it is already in each Finding.evidence). (c) Do NOT emit MilestoneValidating and do NOT emit any fixfeature.created — so fix_cycles is unchanged. (d) Do this REGARDLESS of the fix-cycle cap (escalate immediately). (e) return Ok(None) so the run loop transitions to Blocked via the blocked branch.
6. validation_round()'s match on convert_findings (~3883) must remain exhaustive. Because validation_round findings never carry class=="command-assertion", Escalate cannot legitimately occur there; handle it defensively by emitting MilestoneBlocked with the escalation reason (do not panic, do not create fix features). Keep it minimal.
