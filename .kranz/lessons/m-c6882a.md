A single, durable, repo-specific lesson worth carrying forward:

**In kranz-engine, `preflight()` runs synchronously inside the process's `#[tokio::main]` runtime (called from `run_loop().await`), so any code it reaches that builds its own `tokio::runtime::Runtime` and calls `block_on` panics unconditionally ("Cannot start a runtime from within a runtime"). Engine-side blocking work invoked from an async path must be runtime-free (e.g. `std::net::TcpStream::connect_timeout`, as `backend_readiness::probe_local_reachability` does), NOT `Runtime::block_on` or async `reqwest`. Critically, a plain `#[test]` has no ambient runtime and passes over this panic — so when a validation criterion covers such a path, require a `#[tokio::test]` (or in-runtime run-loop test) that reproduces the runtime context, or the whole green gate stays blind to a guaranteed production crash.**
