This mission's dominant cost was real, repo-specific, and non-obvious: wiring the auth preflight (a new session on the mission-start path) silently desynced MockBackend's FIFO script order in every full-mission test across *both* the engine and server crates — driving three f-2-2 respawns for the green sweep plus recurring out-of-contract-write waivers from an under-scoped touchSet. That's a durable trap a future planner here would not anticipate and would shape how they write the contract, the green-sweep feature, and the touchSet.

Any feature that adds a new backend session or behavior on the mission-start path (e.g. an auth preflight) will consume the first queued MockScript and desync FIFO order in EVERY MockBackend full-mission test across BOTH crates/engine AND crates/server — so spec a test-only seam to pre-seed/skip it (`MissionEngine::seed_worker_auth_verdict_for_test`-style), make a full `cargo test --workspace` green sweep its own explicit feature/step, and list all cross-crate mission-flow test files (engine tests + crates/server tests) in the touchSet up front to avoid repeated out-of-contract-write waivers.
