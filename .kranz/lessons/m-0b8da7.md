Do NOT add `set -o pipefail` to the repo-standard cost/test contract pattern `cargo test --workspace [filter] 2>&1 | grep -qE 'result: ok\. [1-9][0-9]* passed'`. Under pipefail, `grep -q` closes the pipe on its first match while cargo is still writing later crates' output → cargo dies on SIGPIPE (exit 101) and pipefail surfaces that as a false gate failure, even though every test passes. It cost this mission two validation rounds and a red final gate on fully-correct work (all four assertions had to be waived). When a `command` assertion greps cargo output for a passed-count, write the bare pipe (no pipefail), or redirect to a file first (`cargo test ... > out.log 2>&1; grep -qE '…' out.log`), or use `grep -c`/drop `-q` so the pipe drains fully.
