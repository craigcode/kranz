NONE is tempting, but this mission hit a severe, non-obvious, repo-specific trap worth carrying forward — the work-loss cycle that cost the entire M1 milestone a rebuild. Here is the one lesson:

**Lesson:** In this repo the secret scan's generic-secret-assignment rule fires on Rust identifiers literally named `token` (e.g. `let token = …`), which REFUSES the dirty-tree checkpoint commit — and the resulting unblock/worktree-reset cycle can silently discard ALL uncommitted work, leaving HEAD reset to the base SHA (an entire milestone's diff vanished this way). When shaping features that touch engine/CLI/security code, spec workers to (a) name introduced bindings `authority`, not `token` (the codebase's security convention), renaming only local identifiers and never wire/protocol/serde names; and (b) commit their own work within the session against `$KRANZ_BASE_SHA` rather than trusting the dirty-tree checkpoint to preserve it — because if the checkpoint is refused, uncommitted work is lost, not parked. Do not allowlist the scan to work around it.
