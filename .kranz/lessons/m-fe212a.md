A command-type contract assertion that runs `cargo test` with a name filter (e.g. `cargo test -p kranz-engine --test X <name> -- --exact`) passes VACUOUSLY if the filter matches zero tests — cargo exits 0 with "0 filtered out". A future worker renaming or deleting the asserting test would then silently pass the gate. When writing such an assertion, add an anti-vacuity guard: append `2>&1 | grep -q 'result: ok\. [1-9]'` (or assert an exact test count), so the gate fails unless at least one test actually ran and passed. The preflight in this repo already warns on this exact pattern — heed it rather than shipping the bare `cargo test` filter.
