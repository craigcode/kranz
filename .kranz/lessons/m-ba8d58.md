For dashboard (apps/dashboard) visual/CSS bugs — element overlap, text truncation, clipping — write the validation-contract assertion as `agent-judgement` judged against the diff, NOT as a `command`: the test stack is jsdom+vitest, which does no layout and does not apply external stylesheet rules, so a component test can only assert DOM presence/structure (a proxy) and a `getComputedStyle`/layout assertion reads unapplied styles and gives false comfort. Back the fix with correct-by-construction CSS and a DOM-presence proxy test, and expect a validator to (correctly) flag that the proxy doesn't guard the pixels — pre-empt that by scoping the assertion as agent-judgement up front.
