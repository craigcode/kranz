For any new Slack slow-action verb in `crates/slack` (SPEND/hosted actions like draft/new), keep the synchronous gate+ack phase separate from the async host call, and post the hourglass ack BEFORE awaiting the host — packing ack+result into one async fn that awaits the multi-minute host call makes the "immediate" ack arrive only after the work finishes. A FakeHost whose method returns instantly HIDES this ordering, so require a test that proves the ack is produced while the host-call/spawn counter is still 0 (not merely that the ack text contains an hourglass) — otherwise the j5-style "immediate ack" criterion passes green while being broken in production.
