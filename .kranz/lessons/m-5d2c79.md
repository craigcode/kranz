A future backend mission (gemini is explicitly next per the ticket) would hit exactly the non-obvious engine invariant that cost this mission a full f-1-3 respawn. That's the one durable, repo-specific, planning-relevant lesson.

When adding a new `AgentBackend`, its terminal `AgentEvent::Result` MUST carry the full final assistant text: `runner::run_session` sets a run's `final_text` (the string fed to `parse_worker_report`/`parse_validator_report`) SOLELY from the `Result` event's `text` field (runner.rs ~312) — it never accumulates `Text` events. So if a backend's protocol delivers the report as an earlier "message" event followed by a text-less terminal/"done" event (as `codex exec --json` does: `item.completed`/`agent_message` then `turn.completed`), the session must stitch the last message text into the terminal `Result.text`, or reports parse to empty and the worker/validator silently produces zero findings while otherwise looking successful. Spec any new-backend feature to include a fixture-fold test asserting the terminal `Result.text` parses into a report with non-empty content.
