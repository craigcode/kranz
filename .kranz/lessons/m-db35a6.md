For any `MissionHost` operation that must be idempotent-while-live (the drain, or any future "start-once"/debounced host action), reserve the tracker slot BEFORE the `config::load`/`self.backend().await` — not after — because that await is where a second concurrent caller slips through (see the `DrainSlot::{Idle,Starting,Running}` pattern in `crates/server/src/host.rs`). Critically, when writing the validation criterion for such a guard, DEMAND a deterministic regression test that installs the in-flight reservation and asserts a second call is deflected (same `Arc`, no new spawn) — do NOT accept a `tokio::join!(op(), op())` "race" test: on the default current-thread test runtime with an injected `MockBackend` (pre-initialized `OnceCell`), the first future runs to completion before the second is ever polled, so a join! test passes even if the guard is deleted (tautological). This exact trap cost two fix cycles here (ms-1-fix-1-1 then ms-1-fix-2-1).
