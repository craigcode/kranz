When a plan changes a struct field, enum variant, or shared function signature in a declared source file, its touchSet MUST also include the test files that will need compile-forced updates — `crates/*/tests/*.rs` (e.g. the exhaustive `match Command::Serve { .. }` in `crates/cli/tests/cli_test.rs`, router call sites in `crates/server/tests/host_test.rs`) — because the out-of-contract-write sweep flags even a one-token `..` there, and the engine's touchSet is fixed from the approved plan: editing the committed `plan.json` on the mission branch does NOT change it, so the omission cannot be patched after approval and will loop through fix-features. Declare those test paths up front.
