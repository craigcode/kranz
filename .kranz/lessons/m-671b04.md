One lesson stands out as durable, repo-specific, and directly shaping how future contracts get written — the anti-vacuity technique that made every command assertion in this mission bind to real tests and demonstrably held up under the final gate. It's the concrete *solution* to the vacuous-test trap that m-079c36 only warns about.

For **filtered, feature-binding `cargo test` command assertions**, defeat the zero-match vacuous pass two ways together: (1) grep `test result: ok\. [1-9]` (require a *nonzero* passed count, not bare `result: ok\.`), and (2) in each feature's `validationCriteria`, mandate that its tests' names contain a specific substring the contract command filters on (e.g. `cargo test -p kranz-engine <substr>`). A bare `result: ok` filter that matches zero tests — a missing or misnamed test — passes vacuously; the count-guard plus the named-substring binding makes that fail the gate instead. (Keep the broad workspace regression gate as bare `result: ok\.` per m-0b8da7 — the count guard is only for the narrow per-feature filters.)
