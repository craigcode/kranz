When a validation-contract `command` targets the CLI crate, use `cargo test -p kranz` (not `-p kranz-cli`): the CLI crate at crates/cli is `[package] name = "kranz"` (lib `kranz_cli`, bin `kranz`), so `-p kranz-cli` errors with "did not match any packages" and the piped `grep` guard can never pass — a broken assertion regardless of whether the behaviour is correct. The sibling crates do match their intuitive `-p` names (`kranz-engine`, `kranz-server`, `kranz-slack`); only the CLI is the exception. Note that Dockerfile:35 already uses the non-existent `-p kranz-cli` and is a latent breakage, so do not copy package names from there.
