# v0.4.1 maintenance release preparation

This patch release packages the dependency refresh from PR #77 and the ACP
operational fixes from PR #78. It adds no new worker backend, terminal provider,
gate authority or mission schema. The review-effort pilot remains a separate
draft; this release makes no claim about human review efficiency.

## Changes and compatibility

An expired ACP permission request now closes its own response channel without
cancelling sibling candidates. Fixed-profile egress refusals explain the mission
grant mismatch without printing destinations. Operator documentation describes
which controls cancel and join an active batch before processing.

Filtered Docker egress requires a recognized stable daemon version of at least
25.0.5. Older versions, prerelease versions and unrecognized vendor strings are
refused before provisioning. This is a conservative DNS prerequisite, not a
claim that every older daemon is vulnerable or every newer runtime is qualified.
Existing qualified profile, host and adapter limits still apply. Cache
readability and relay reachability from the default bridge remain documented
trust assumptions; stronger cache and relay isolation is follow-up work.

Dashboard and experimental Even G2 dependencies and CodeQL action pins are
updated. The embedded dashboard was rebuilt with the reviewed dependency lock.
Workspace crates, sibling requirements, Tauri metadata, README install links and
dependency notices advance together to 0.4.1. Existing event and configuration
formats are unchanged.

## Review and evidence

Correctness review traces permission expiry to the individual request and
checks the Docker prerequisite before namespace provisioning. Readability review
keeps restrictions and unverified assumptions explicit. Architecture review
retains the current broker and containment boundaries. Security review checks
the absence of destinations in the refusal message and keeps required container
proofs fail-closed. Performance review finds no added work in ordinary mission
event processing; the bounded Docker version probe precedes egress setup.
This is the preparing assistant's review, not an independent audit.

The underlying regression and container evidence is recorded in the
[ACP operational review](2026-09-22-acp-operational-followups.md). This release
still requires its own complete workspace and application gates, package
inspection and dry run, protected PR/main checks, main-commit release rehearsal,
and native archive smoke on all five platforms. Tagged rebuilds require their
own archive checks and publication approval through the existing protected
environment. Registry uploads proceed bottom-up, with each dry run and uploaded
package verified before continuing, followed by an isolated registry install.
Exact commits, workflow runs and artifact digests belong in the release receipts;
this preparation note alone does not certify publication.
