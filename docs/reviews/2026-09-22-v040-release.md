# v0.4.0 release preparation

This minor release packages the human review packet, opt-in baseline/candidate
observations, recorded outcome reasons and the Sgian worker coordination lane.
The release also includes the pilot protocol and preparation receipts; the three
pilot cases and human review measurements remain outstanding.

## Compatibility and scope

Workspace crates, sibling requirements, Tauri metadata, README installation
references and dependency notices align at 0.4.0. A minor version distinguishes
the new capabilities and evolving pre-1.0 Rust report/contract APIs. Existing
wire fields remain compatible; absent optional fields preserve older reports
and plans. The baseline-pair contract is documented in its
[contract change review](2026-09-22-baseline-candidate-contract.md).

Human packets and outcome reasons are read-only projections. Baseline/candidate
controls remain advisory evidence and never replace required stage receipts or
human authority. Source/configuration matching does not attest mutable tool
binaries, caches or external services. Qualified ACP profiles and their existing
platform limits are unchanged. This release does not claim new live-provider
qualification, production cutover or measured review-efficiency gains.

## Sgian corrections found during preparation

The merged helper's deadline covered a running child but joined its pipe-reader
thread without a deadline after leader exit. A descendant retaining stdout could
therefore block worker startup or revocation indefinitely. The lane now reuses
the existing bounded exact-output supervisor: it limits stdout/stderr, drains
both concurrently, retains the unreaped leader until pipe completion, and kills
the supervised process tree on timeout or oversized output. Its existing Windows
Job assignment precedes execution.

An owned worker guard attempts credential revocation on normal return, error and
dropped worker futures. It is not crash recovery: host/engine death, ambiguous
issuance and failed revocation may leave daemon credentials requiring operator
reconciliation. The helper uses the existing discovery environment allowlist
with HOME for socket lookup; provider secrets and client tokens are not inherited.
Helper reply bytes are excluded from failure logs. The shared scrubber now
recognizes the fixed client-token shape even without an assignment label; a
regression checks bare output, structured evidence and short non-secret examples. No daemon socket is mounted
through a worker sandbox by this coordination lane.

Regression checks exercise the exited leader with a pipe-holding descendant,
positive control for that descendant's effect, oversized stdout/stderr, private
stderr exclusion, child environment filtering, and normal versus dropped worker
futures. Tests use local fake helpers; they do not contact a live Sgian daemon or
provider. The runner fixture isolates its binary override in a subprocess.

## Five-axis review

Correctness review follows the exact source/event bindings in the three evidence
features and cancellation ownership in the Sgian lane. Readability review keeps
historical findings, current state, incomplete evidence and uncertain cleanup
distinct. Architecture review reuses existing folds, exports and process
supervision; it adds no execution factory or dependencies. Security review checks
bounded subprocess output, stripped ambient credentials, unchanged authority and
honest best-effort cleanup. Performance review retains the report memo and bounded
control calls; full-history reports remain unpaginated and no scalability claim
is made. This is the preparing assistant's review, not an independent audit.

## Verification boundary

Candidate workspace, dashboard, packaging and documentation checks must pass,
followed by all required PR/main checks, a main-commit release rehearsal and five
native archive smoke jobs. An annotated tag must name that same tested main
commit. The protected release environment remains the final publication gate;
tagged builds require their own archive checks. Registry packages must be dry-run
and published bottom-up, then installed from the registry for confirmation.
Exact candidate and publication receipts belong in the PR and release notes.
This preparation document alone does not certify a tag, binary or registry upload.
