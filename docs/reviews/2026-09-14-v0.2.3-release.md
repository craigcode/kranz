# v0.2.3 security release review

This patch distributes the rustls correction reviewed in
[the dependency update](2026-09-14-rustls-security-update.md). The workspace
and standalone Tauri graph retain rustls 0.23.45. Version preparation changes
only Kranz's own package versions in the two lockfiles.
The regenerated notice inventory changes the same four workspace version
labels; upstream license text is unchanged.

## Scope and compatibility

All four registry packages and the Tauri metadata use 0.2.3. The CLI archive
matrix remains Linux x86_64, macOS ARM64/x86_64, and Windows ARM64/x86_64.
Tauri remains build-checked, without a signed desktop distribution claim.
There is no mission schema, authorization, backend-default, or configuration
migration in this patch. ACP and external gate tickets remain future work.

The archive smoke script is carried forward unchanged from the v0.2.2
verification branch. Its workflow is now manually dispatched with an explicit
build run, source ref, source commit, and expected version. It downloads the
already-built archive, checks release-workflow provenance and native binary
architecture, then runs version/help/licenses outside a source checkout.
The executed CLI receives only the minimal host environment and a temporary
home; workflow credentials are not forwarded to it.

## Five-axis review

- **Correctness:** package and Tauri versions align; sibling requirements move
  together; published archives must bind to the exact tagged source. Rehearsal
  and tag builds receive separate native-execution receipts.
- **Readability:** one manual workflow replaces hard-coded release identifiers;
  the release instructions distinguish source checks, artifact checks, and
  publication. The upstream advisory is linked without overstating its impact.
- **Architecture:** the existing release matrix, packaging, attestations, and
  protected publish job are preserved. The verifier executes archived binaries
  rather than substituting a fresh local build.
- **Security:** the fixed rustls minimum, locked graphs, and notices remain in
  place. Verification permissions are read-only; provenance failure prevents
  execution. Required checks and the owner-approved release environment still
  control publication. Existing secret and domain checks remain mandatory.
- **Performance:** no runtime algorithm changes. The added manual verification
  runs on five native hosts and has a ten-minute limit per job.

This is a recorded self-review, not an independent security audit. Candidate
validation results and exact CI run links are recorded in the version pull
request. Publication requires passing main CI, a source/build rehearsal,
native archive checks, and the protected release job. Final release notes carry
the artifact and registry-install receipts; this source review alone does not
certify a published binary.
